# مصروف

تطبيق Android لإدارة المال محليًا، يحوّل رسائل البنوك المدعومة إلى حركات مالية قابلة للمراجعة وملخصات للحسابات والبطاقات والالتزامات والمصاريف.

[English](README.md)

## المزايا

- استيراد الرسائل التاريخية لبنوك وفترة استلام محددة، ومعالجة الرسائل الجديدة مع منع التكرار وحفظ محاولات التعافي.
- محرك تفسير بقواعد وأدلة وتحقق، مع تأكيد ملكية الحسابات والبطاقات. تعريفات الجزيرة والأهلي وبرق والإمارات دبي الوطني وساب والإنماء مرفقة، وستة قوالب STC تحتاج اعتمادًا ماليًا صريحًا.
- تعلم آلة محلي يساعد في أنواع الرسائل المؤهلة ويتعلم من التصحيحات الصريحة؛ لا يخترع مبلغًا أو ملكية أو موافقة مالية.
- لوحة لدورة الراتب، وتفاصيل الحركات، ومركز مراجعة، وحسابات وبطاقات وتسهيلات وقروض والتزامات.
- توقعات المشتريات واقتراحات الدفعات المتكررة وسجل الصرف ومركز تنبيهات موحد. إشعارات الهاتف اختيارية.
- العربية واتجاه RTL والإنجليزية، والثيم والمكونات المشتركة، والمظهر الفاتح والداكن والنظام.
- نسخ احتياطية مشفرة واستعادة متينة، مع بيانات التحليل وأنماط الرسائل؛ النسخ المالية المقبولة بإصدار 18 فقط.

## هيكل المشروع

| الوحدة | المسؤولية |
| --- | --- |
| `app` | الواجهات ومسارات التطبيق واستقبال الرسائل والتخزين والتعافي |
| `bank-engine` | تفسير الرسائل وقواعد البنوك وأدلة الاستخراج، بوحدة Kotlin مستقلة |
| `finance-core` | القيم والفترات والهويات والسياسات المالية والتصنيف والمطابقة والتجميع |
| `ml-assist` | مساعدة التصنيف والتوقعات واكتشاف التكرار محليًا |
| `ui-kit` | الثيم والخطوط والمكونات والرسوم المشتركة |

المحرك والتحليل المعتمدان يعملان مباشرة داخل مصروف. لا توجد شاشة مختبر أو مساحة بيانات موازية أو نسخة مولدة من التطبيق. بقيت بعض أسماء حزم Kotlin الداخلية لتجنب تغييرات شكلية غير لازمة.

## البناء والتحقق

استخدم JDK 17 واضبط مسار Android SDK في `local.properties`.

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest --tests '*MessagePatternsWorkflowTest'
./gradlew lintDebug detekt
python3 ml-assist/tools/train_family_model.py --check
python3 ml-assist/tools/test_training.py
```

تصدّر الاختبارات خصائص التدريب المنظفة بكود Kotlin نفسه إلى `app/build/model-training/features.json`، ثم يتحقق أمر التدريب من النموذج المرفق. تعمل اختبارات الوحدة الكاملة في CI للطلبات وmain؛ محليًا تُشغّل الاختبارات المستهدفة. اختبارات الجهاز والانقطاع وتحديث APK ضمن CI. إصدار APK يعتمد نجاح CI أولًا.

## البيانات والتحديث

تبقى قاعدة الفعلي `masroof.db` بإصدار 18 فقط. تُرفض قواعد البيانات والنسخ المالية الأقدم دون ترحيل أو مسح تلقائي. يحفظ التحديث الحركات والرسائل ومعرفاتها والملكية والتصحيحات والالتزامات والإعدادات. بيانات التعلم والتحليل في `learning.db` و`analytics.db`. لا تُستورد بيانات المختبر القديمة ولا تُمسح تلقائيًا. تحديث المحرك والنموذج يعالج غير المحسوم، ويحفظ الحركات المسجلة والقرارات اليدوية.

يطلب التطبيق صلاحية الرسائل للاستيراد والاستقبال الحي. البيانات المالية محلية والنسخ السحابي التلقائي للنظام معطل. يستخدم الاتصال بالشبكة لميزات أسعار الصرف وتحديث التطبيق الموجودة. النسخ المصدرة محمية بكلمة مرور. التوقعات استشارية ولا تسجل حركات مالية.
