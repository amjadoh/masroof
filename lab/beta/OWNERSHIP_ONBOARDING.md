# Beta ownership onboarding

The production setup and shared theme/components are the reference. The implemented journey is welcome → permission → import date/history → grouped account/card ownership → completion summary → Home. Bank routing occurs during import using the supported BankEngine catalog.

Ownership is one explicit decision per bank-qualified observed reference, never a per-message question or a suffix-derived entity identity. Conflicting card kinds stay reviewable; colliding registry identities require selection. A fixed footer exposes Finish when ownership is resolved. Missing card configuration does not block finishing setup.

Clear eligible operations post automatically after ownership. A confirmed credit card can show independently proven purchases/refunds without an invented shared facility or statement due. Debit account relationships and unknown card types still gate the affected facts. The primary-card editor creates its internal facility atomically on Save; supplementary cards choose their primary. Closing the draft does not create either.

Fresh schema14 has16 physical tables and10 read-only views. No old lab migration is registered. Storage and backup recovery use the independent v2 namespace. The production app, parser and shared UI module are unchanged. Live SMS registration is limited to the separate standalone lab host.

Current decisions, changes in ownership, corrections, retries and reservations preserve financial authority and audit history. The dashboard only reads persisted facts; it never performs reconciliation or reparses message bodies.
