# تقرير تنفيذ تحسينات مختبر مصروف ٢

نُفذت إعادة تنظيم التخزين ورحلة الإعداد والعرض داخل `lab/` فقط. المرجع هو دورة مصروف الفعلي والثيم والمكونات المشتركة، مع استمرار BankEngine وFinance Core المستقلين. هذا التقرير يصف التنفيذ على الفرع `feat/lab-production-parity`، انطلاقًا من `1a6cd33a`.

## النطاق والعزل

لم تتغير مصادر `app/` أو `ui-kit/` أو ملفات CI. تعديل `gradle.properties` الموجود مسبقًا في مساحة العمل ليس ضمن هذا العمل ولن يُضم إلى الالتزام.

قاعدة المختبر الجديدة `masroof_beta_v2.db` وتفضيلاته `masroof_beta_v2_prefs`؛ تبدأ فارغة. لا ترحيل للبيانات القديمة، ولا قراءة أو حذف لقاعدة الفعلي أو قاعدة المختبر القديمة. النسخ والاستعادة في هذه النسخة يدعمان المخطط الحالي فقط، مع رفض النسخ القديمة دون تحويلها.

أُضيف مضيف مستقل داخل `lab/upgrade-host` بحزمة `com.baraa.masroof.lab.standalone` لتجربة الرحلة واستقبال SMS دون تعديل تطبيق الفعلي. المستقبل والتهيئة الحية مسجلان في هذه الحزمة فقط. فتح المختبر المضمّن في مصروف يظل متاحًا، والاستقبال الحي المستقل يحتاج تثبيت حزمة المختبر المستقلة.

## قاعدة البيانات: ١٦ جدولًا فعليًا

أصبح العدد ١٦ بدل ٢٤: ١٤ جدولًا تقابل مسؤوليات جداول مصروف الفعلي، وجدولان للتحسينات. ليست نسخة حرفية من DDL الفعلي؛ احتُفظ بعقود المحرك الجديد وإصداراته وسلطات التصحيح.

| # | الجدول | المسؤولية |
| --- | --- | --- |
| ١ | `beta_raw_evidence` | الرسالة الأصلية ووقت الاستقبال ومصدره |
| ٢ | `beta_raw_sms_provider_alias` | ربط معرف المصدر بالرسالة المحفوظة ومنع تكرار الحي والتاريخي المطابق |
| ٣ | `beta_parsed_event` | التفسير الحالي والحقائق المكتوبة بواسطة المعالجة؛ حقول مفهرسة للفترة والرصيد |
| ٤ | `beta_bank_selection` | البنوك المفعلة |
| ٥ | `beta_account_registry` | الحسابات وأسماؤها وأنواعها |
| ٦ | `beta_card_registry` | البطاقات والشبكة والنوع وروابطها |
| ٧ | `beta_credit_facility` | التسهيل الائتماني المشترك |
| ٨ | `beta_loan_registry` | القروض وأنواعها |
| ٩ | `beta_financial_transaction` | العملية المالية الحالية وحقولها القابلة للاستعلام |
| ١٠ | `beta_financial_transaction_raw_sms_link` | حجز الأدلة وربطها بالعملية/التصحيح |
| ١١ | `beta_commitment` | الالتزامات وقرارات سدادها اليدوية |
| ١٢ | `beta_review_item` | حالة الاعتماد المالي وقرارات ملكية المراجع |
| ١٣ | `beta_correction_current` | التصحيح اليدوي الحالي |
| ١٤ | `beta_processing_retry` | محاولات التفسير والاعتماد المتعثرة |
| ١٥ | `beta_audit_log` | تاريخ التفسير والمال والقرارات والأسماء البديلة والإعدادات |
| ١٦ | `beta_learning_label` | التسميات البشرية ومصدرها للتعلم |

مصدر العدد هو [مخطط Room 14](schemas/com.baraa.masroof.lab.beta.data.BetaDatabase/14.json)، وتعريفه في [BetaDatabase.kt](src/main/kotlin/com/baraa/masroof/lab/beta/data/BetaDatabase.kt).

توجد ١٠ واجهات SQL للقراءة فقط (`VIEW`) لتوافق العقود الداخلية. لا تخزن نسخًا إضافية من البيانات ولا تزيد عدد الجداول المخزنة. حقائق الداشبورد التشغيلية أصبحت أعمدة داخل سجل التفسير بدل جدولين مستقلين.

التحسينات تشمل مفاتيح خارجية، وفهارس الوقت والهوية، وفصل هوية الكيان عن آخر أربعة أرقام، وتاريخ القرارات، وحقول تشغيلية للاستعلام بدل فك تاريخ JSON كاملًا عند كل عرض. يبقى JSON للأرشيف والعقود المركبة التي يحتاجها المحرك.

## دورة الإعداد التي سيشاهدها المستخدم

١. بدء الإعداد، أو الاستعادة من نسخة مختبر متوافقة.

٢. منح صلاحية الرسائل. إذا كانت ممنوحة ينتقل التطبيق مباشرة إلى الفترة.

٣. اختيار بداية الشهر، أو آخر ٣٠ يومًا، أو آخر يوم ٢٧، أو تاريخ مخصص، ثم الاستيراد. يستمر التقدم المحفوظ بعد الانقطاع.

٤. عرض الحسابات والبطاقات مجمعة لاعتماد «ملكي/ليس لي»، بدل سؤال مستقل لكل رسالة. البنك يُكتشف أثناء القراءة وفق المحرك؛ لا توجد خطوة إجبارية إضافية لاختيار البنك.

٥. زر إنهاء واضح وثابت بعد حسم الملكية. نقص علاقة البطاقة لا يمنع إنهاء الإعداد؛ التعارض الحقيقي يبقى للمراجعة.

٦. ملخص الإعداد ثم الرئيسية. العمليات الواضحة المؤهلة تُضاف تلقائيًا. لا يُطلب اعتماد جميع الرسائل يدويًا.

حالة البطاقة الائتمانية المؤكدة بلا تسهيل موثق لم تعد تجعل الصفحة فارغة: يظهر إنفاق البطاقة المثبت، ولا يُختلق مستحق مشترك. أما بطاقة الخصم التي لا يُعرف حسابها، أو النوع المجهول، فتظل المقاييس التي تتطلب هذه المعلومة غير متاحة حتى تصحيحها.

## الواجهة والإعدادات

تستخدم الواجهة ثيم مصروف ومكوناته المشتركة، ونفس تنظيم الرئيسية والتنقل بين الرئيسية والعمليات والمراجعة والإعدادات. الفترة الافتراضية دورة الراتب من يوم ٢٧ مع تقديم الجمعة وتأخير السبت، بدل افتراض الشهر الميلادي لكل المقاييس.

| المجال | التنفيذ |
| --- | --- |
| الرئيسية | القيم المثبتة وحالات النقص وإجراءات الاستكمال، مع تحديث العرض بعد الكتابات |
| الحسابات | إضافة وتحرير الاسم والنوع والملكية بهوية مستقلة |
| البطاقات | النوع والشبكة وأساسية/إضافية والربط؛ لا سؤال تقني منفصل لإنشاء تسهيل |
| محرر الكيان | Bottom sheet بأزرار حفظ وإلغاء ثابتة ومسودة لا تُطبق بالإغلاق |
| القروض | الاسم والنوع؛ تغيير النوع يعيد الأثر المتأثر إلى التحقق |
| الالتزامات | الإعداد والتكرار ونطاق الأشهر وقرارات الدفع اليدوية |
| اللغة والمظهر | تفضيلات مستقلة للمختبر؛ العربية وRTL والإنجليزية والمظهر الفاتح/الداكن/النظام |
| البيانات | النسخ والاستعادة وإعادة الضبط؛ إعادة الضبط تعيد الإعداد دون مساس بالفعلي |
| تخصيص الرئيسية | إعدادات العرض الحالية محفوظة ومستقلة عن المبالغ |

«مشابه للفعلي» هنا يصف رحلة SMS الأساسية وبنية الواجهة والمكونات، ولا يعني استبدال المختبر بمحرك الفعلي. أداة مقارنة كشف CSV الموجودة في الفعلي ليست من الشاشات المنفذة في هذا الفرع؛ لم تتغير بسبب إعادة التنظيم هذه. لذلك لا يُدّعى تكافؤ كل أدوات التطبيق الفرعية.

## المعالجة الحية والاستيراد

الدورة الحية في الحزمة المستقلة: استقبال ← حفظ دائم ← جدولة بمعرف الرسالة وجيل التخزين فقط ← تفسير ← اعتماد الواضح أو إبقاء الغامض للمراجعة ← تحديث العرض. لا يُرسل نص الرسالة إلى WorkManager.

وقت الاستقبال يعتمد وقت مركز الخدمة الصحيح، وللرسائل متعددة الأجزاء أبكر وقت صحيح؛ وإلا ساعة الجهاز. تتكرر المحاولة عند فشل التنفيذ، وتبقى المحاولة المحفوظة قابلة للاستئناف. إعادة الضبط والاستعادة تغيران جيل التخزين لإبطال مهام النسخة السابقة.

الاستيراد التاريخي يحتفظ بالدفعات والتقدم، دون حد ٩٠ يومًا الإجباري السابق. الالتقاط الحي ثم التاريخي المطابق تمامًا يحفظ هوية واحدة وأثرًا ماليًا واحدًا. الرسائل المتشابهة زمنيًا دون إثبات التطابق تبقى للمراجعة بدل دمجها بالتخمين.

الداشبورد قارئ فقط. يستعلم عن الفترة المطلوبة وآخر المشاهدات اللازمة للأرصدة والمستحقات، ولا يعيد تفسير SMS ولا يفك تاريخ العمليات كله. اختُبرت حالة ١٠٬١٠٠ صف قديم خارج الفترة مع ميزانية قراءة صفّين للفترة الحالية.

## حجم التغيير

شمل التنفيذ ١٢٨ ملفًا داخل المختبر، ونحو ٤٤٠٠ سطر مضاف و١٦٠٠ محذوف في التغييرات البرمجية والمخطط والاختبارات. منها ٢٢٥١ سطرًا لمخطط Room المُصدّر، إضافة إلى الاختبارات وتحديثها وإلغاء اختبارات الترحيل القديمة. ليس هذا العدد جداول جديدة: الإجمالي المخزن هو ١٦ فقط. إعادة توجيه التخزين والإعداد والتعافي والعرض هي سبب اتساع التغيير.

## ما بقي محفوظًا في المحرك والتعلم

BankEngine وقواعد البنوك ومسار Less Code باقية. Finance Core ما زال يحسب المال ويطبق بوابات الثقة والملكية والتصحيح؛ التعديل المحدد يسمح بإنفاق البطاقة الائتمانية المؤكدة عندما تكون علاقة التسهيل مجهولة، دون احتساب مستحق مخترع.

تسميات ML البشرية محفوظة في جدول التعلم. هذا الفرع لا يضيف تدريبًا أو استدلالًا آليًا ولا يفعّل ML. لم تعد واجهة experiment. دعم البنوك الفعلي هو ما يقدمه الكتالوج الحالي للمحرك؛ لا توسعة صامتة إلى بنوك غير مدعومة.

## التحقق والنتائج

الاختبارات المحلية على Android API 35 وببيانات اصطناعية مستقلة. نجحت اختبارات JVM: ٢٧٤ للمختبر، و١٧٩ للنواة المالية، و٥٦ للمحرك، بإجمالي ٥٠٩ اختبارات. نجح lint للمختبر والمضيف المستقل وبناء APK، وفُحص manifest الفعلي للتأكد من غياب مستقبل المختبر وتهيئته الحية.

أثبت اختبار فشل متعمد حفظ محاولة تسجيل العملية الحية وإعادة تنفيذها، وحفظ هوية واحدة عند التقاء الالتقاط الحي والاستيراد التاريخي، وإبطال المهام القديمة عند إعادة الضبط والاستعادة. جرى اختبار استعلام الفترة أمام ١٠٬١٠٠ صف قديم خارجها، وتحرير البيانات الوصفية بمراجعة تمنع حفظ المسودات القديمة.

اختبار Android الحي شمل أيضًا إرسال SMS عبر خدمة المحاكي: أضيفت عملية سحب بـ١٧ ريالًا مرة واحدة بوقت مركز الخدمة، وأصبحت قائمة المحاولات المعلقة فارغة. أزيلت رسالة المحاكاة من مزود الرسائل بعد التحقق لتنظيف بيئة الاختبارات.

نجحت كذلك الاختبارات الثلاثة للمضيف المستقل: الإعداد حتى الرئيسية وإنفاق البطاقة دون اختلاق تسهيل، وWorkManager مع تسجيل واحد، واستئناف الرسالة المعلقة بعد الاستعادة بجيل جديد. ونجحت ٣٩ مرحلة لاختبارات انقطاع العملية، وتشمل الصلاحيات والاستيراد والعمليات والتصحيحات والتعلم واستعادة ملفات WAL.

نجحت حزمة Android كاملة: ١٥٠ اختبارًا على المحاكي، بلا أخطاء، في نحو ٤ دقائق و٤٤ ثانية. تشمل الملكية والاستيراد والتصحيحات والنسخ والأرشيف والداشبورد بالعربية وRTL والمظهر الداكن والخط الكبير وإعادة إنشاء الشاشات.

نجحت تجربة تحديث APK الموقّع داخل الحزمة المعزولة: بقيت ٦٠٠ عملية، منها ٥٨٥ نشطة، وتاريخ التصحيحات والتدقيق والهوية المشفرة، ونجحت الاستعادة بعد التحديث ورفض كلمة المرور الخاطئة والملف المعدل دون تغيير الحالة الحالية. يستخدم الإصداران المخطط الجديد ١٤ نفسه.

المراجعة والكود في [PR #302](https://github.com/bakhshb/masroof/pull/302)، و[حالة GitHub CI الحالية](https://github.com/bakhshb/masroof/pull/302/checks). لا تعني إتاحة الفرع أنه دُمج إلى main.

## لقطات من الرحلة

لقطات عربية من محاكي المختبر المستقل ببيانات اصطناعية. يعرض ملف HTML الفترة والملكية والاكتمال والرئيسية والإنفاق. صافي حركة الحسابات صفر في مثال بطاقة ائتمانية فقط؛ إنفاق البطاقة يظهر في قسم المصاريف ولا يتحول إلى سحب من حساب غير موثق.

## تجربة النسخة

للبناء المستقل: `./gradlew :lab:upgrade-host:assembleStandaloneDebug`. ملف APK داخل `lab/upgrade-host/build/outputs/apk/standalone/debug/`.

ابدأ بالإعداد، اختر الفترة، استورد، ثم اعتمد الحسابات والبطاقات. بعد إنهاء الإعداد ينبغي أن تظهر العمليات الواضحة في الرئيسية والعمليات؛ مركز المراجعة للحالات المحتاجة فعلًا. يمكن استكمال ربط البطاقات من الإعدادات ← البطاقات. إعادة الضبط من إعدادات المختبر تعيد التجربة إلى البداية.
